## 快速开始

### 一键运行（开发环境）

```bash
cd bilibili-monitor

# 创建虚拟环境

# 安装依赖

# 运行采集（测试模式）
```

## 定时任务配置

### 方式对比

| 特性 | Systemd Timer | Cron | Launchd |
|------|--------------|------|----------|
| **平台** | Linux | 跨平台 | macOS |
| **日志集成** | ✅ journalctl | ❌ 需自行配置 | ❌ 需自行配置 |
| **失败重试** | ✅ 内置支持 | ❌ 不支持 | ⚠️ 有限支持 |
| **资源限制** | ✅ 完整支持 | ❌ 不支持 | ✅ 基本支持 |
| **依赖管理** | ✅ After/Before | ❌ 无 | ⚠️ 基础支持 |
| **易用性** | 中等 | 简单 | 中等 |

**推荐选择**：
- 开发环境（macOS）：使用 **Launchd**
- 生产环境（Linux）：使用 **Systemd Timer**

---

### 方式一：Systemd Timer（生产环境推荐）

#### 1. 创建 Service 文件

**文件路径**：`/etc/systemd/system/bilibili-monitor.service`

```ini
[Unit]
Description=Bilibili Monitor - Data Collection Service
Documentation=https://github.com/aramisjiang-wq/embodied-marketing
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
Group=root
WorkingDirectory=/opt/embodied-marketing
ExecStart=/opt/embodied-marketing/venv/bin/python /opt/embodied-marketing/scripts/collect.py
Restart=on-failure
RestartSec=60
StandardOutput=append:/opt/embodied-marketing/logs/collect.log
StandardError=append:/opt/embodied-marketing/logs/collect.log

# 资源限制（防止单次采集占用过多资源）
MemoryMax=512M
CPUQuota=50%

# 环境变量
Environment="PYTHONUNBUFFERED=1"
Environment="DB_PATH=/opt/embodied-marketing/bilibili_monitor.db"
Environment="LOG_DIR=/opt/embodied-marketing/logs"

# 安全加固
NoNewPrivileges=yes
ProtectSystem=strict
ReadWritePaths=/opt/embodied-marketing

[Install]
WantedBy=multi-user.target
```

#### 2. 创建 Timer 文件

**文件路径**：`/etc/systemd/system/bilibili-monitor.timer`

```ini
[Unit]
Description=Bilibili Monitor - Daily Collection Timer
Requires=bilibili-monitor.service

[Timer]
# 每天凌晨 00:05 执行（避开整点高峰）
OnCalendar=*-*-* 00:05:00
# 随机延迟0-300秒（避免多台服务器同时执行）
AccuracySec=300s
# 如果错过时间（如关机），启动后立即补执行
Persistent=true

[Install]
WantedBy=timers.target
```

#### 3. 启用并启动服务

```bash
# 复制配置文件到系统目录
sudo cp scripts/bilibili-monitor.service /etc/systemd/system/
sudo cp scripts/bilibili-monitor.timer /etc/systemd/system/

# 重载systemd配置
sudo systemctl daemon-reload

# 启用开机自启
sudo systemctl enable bilibili-monitor.timer
sudo systemctl enable bilibili-monitor.service

# 启动定时器（开始计时）
sudo systemctl start bilibili-monitor.timer

# 查看状态
sudo systemctl status bilibili-monitor.timer
sudo systemctl list-timers bilibili-monitor.timer

# 手动触发一次采集（不等待定时器）
sudo systemctl start bilibili-monitor.service

# 查看实时日志
journalctl -u bilibili-monitor.service -f
```

#### 4. 验证定时任务是否生效

```bash
# 方法1：查看下次执行时间
systemctl list-timers bilibili-monitor.timer

# 方法2：查看最近的服务调用记录
journalctl -u bilibili-monitor.service --since "today" --no-pager

# 方法3：检查采集日志的时间戳
tail -20 /opt/embodied-marketing/logs/collect.log
```

### 方式二：Cron（传统方式）

```bash
# 编辑crontab
```

**Cron表达式参考**：

| 表达式 | 含义 | 示例 |
|--------|------|------|
| `5 0 * * *` | 每天00:05 | ✅ 推荐配置 |

| `0 */2 * * *` | 每2小时的整点 | 中频采集 |

### 日志系统架构

```
bilibili-monitor/
├── logs/

│   └── performance.log      # 性能指标统计

├── collect_status.json      # 当前采集状态（JSON格式）
└── run_logs                 # 数据库中的采集历史记录
```

### 日志格式说明

**标准日志格式**：
```
2026-01-09 00:05:01,234 INFO [main] Starting data collection for brand: LimX
2026-01-09 00:05:02,456 DEBUG [api] Fetching video list from Bilibili API...
2026-01-09 00:05:03,789 WARNING [rate_limit] Approaching rate limit, adding delay
2026-01-09 00:05:04,012 ERROR [database] Failed to insert record: UNIQUE constraint failed
```

**字段解析**：
- **时间戳**：精确到毫秒
- **日志级别**：DEBUG / INFO / WARNING / ERROR / CRITICAL
- **模块名称**：[main] / [api] / [db] / [rate_limit] 等
- **消息内容**：具体操作描述

#### 2. 状态文件监控

**collect_status.json 结构**：

```json
{
  "is_running": true,
  "started_at": "2026-01-09T00:05:00+08:00",
  "current_brand": "LimX",
  "progress": {
    "total_brands": 3,
    "completed_brands": 1,
    "current_video_index": 45,

  },
  "statistics": {
    "videos_processed": 456,
    "errors_count": 12,
    "api_calls_made": 1234
  }

```

**监控脚本示例**：

```bash
#!/bin/bash
# check_collect_status.sh - 快速检查采集状态

STATUS_FILE="/opt/embodied-marketing/collect_status.json"

if [ ! -f "$STATUS_FILE" ]; then
    echo "⚠️  状态文件不存在"
    exit 1
fi

IS_RUNNING=$(jq -r '.is_running' "$STATUS_FILE")

if [ "$IS_RUNNING" = "true" ]; then
    BRAND=$(jq -r '.current_brand' "$STATUS_FILE")
    PROGRESS=$(jq '.progress' "$STATUS_FILE")
    echo "✅ 采集中 - 品牌: $BRAND, 进度: $PROGRESS"
else
    LAST_RUN=$(jq -r '.last_completed_at // "未知"' "$STATUS_FILE")
    echo "⏸️ 空闲中 - 上次完成: $LAST_RUN"
fi
```

### 日志轮转配置

防止日志文件过大，配置自动轮转：

**方案一：logrotate（推荐）**

```bash
# 创建配置文件 /etc/logrotate.d/bilibili-monitor
/opt/embodied-marketing/logs/*.log {
    daily
    missingok
    rotate 14
    compress
    delaycompress
    notifempty
    create 0644 root root
    postrotate
        systemctl reload rsyslog >/dev/null 2>&1 || true
    endscript
}

# 测试配置
logrotate -f /etc/logrotate.d/bilibili-monitor
```

**方案二：Python内置logging.handlers.RotatingFileHandler**

在 `collect.py` 中配置：

```python
import logging
from logging.handlers import RotatingFileHandler

logger = logging.getLogger('bilibili_monitor')
handler = RotatingFileHandler(
    'logs/collect.log',
    maxBytes=10*1024*1024,  # 10MB
    backupCount=7            # 保留7个备份
)
formatter = logging.Formatter(
    '%(asctime)s %(levelname)-8s [%(name)s] %(message)s',
    datefmt='%Y-%m-%d %H:%M:%S'
)
handler.setFormatter(formatter)
logger.addHandler(handler)
```

## 故障排查速查表

### 常见错误及解决方案

#### ❌ 问题1：采集超时或长时间无响应

**症状**：
- 采集进程运行超过30分钟未结束
- 日志停留在某条记录后长时间无更新

**可能原因及解决方案**：

| 原因 | 诊断方法 | 解决方案 |
|------|---------|---------|
| B站API限流 | 日志出现 `429 Too Many Requests` | 增加延迟至3-5秒 |
| 网络连接不稳定 | `curl` 测试B站API连通性 | 配置重试机制 |
| 数据库锁定 | `lsof` 检查数据库文件占用 | 确保只有一个实例运行 |
| 内存不足 | `free -h` 查看可用内存 | 减少并发数或增加swap |

**快速修复命令**：

```bash
# 1. 查看当前进程状态
ps aux | grep collect.py

# 2. 如果卡住，强制终止
pkill -9 -f collect.py

# 3. 清理状态文件
echo '{"is_running": false}' > collect_status.json

# 4. 以调试模式重新运行
python scripts/collect.py --debug --brand "LimX"
```

---

#### ❌ 问题2：大量403 Forbidden错误

**症状**：
- 日志频繁出现 `HTTP 403 Forbidden`
- 采集成功率骤降至50%以下

**解决方案**：

```bash
# 1. 更新Cookie（最有效）
# 登录 https://www.bilibili.com 后，从浏览器复制Cookie
export BILIBILI_COOKIE="你的新Cookie"

# 2. 使用代理IP池（高级）
# 在 .env.local 中配置：
# HTTP_PROXY=http://proxy-pool:port

# 3. 降低采集频率
# 修改 REQUEST_DELAY = 5.0  （增加到5秒）

# 4. 分散采集时间
# 将定时任务改为每天多次，每次只采集1-2个品牌
```

---

#### ❌ 问题3：数据库损坏或锁定

**症状**：
- 报错 `database is locked`
- `sqlite3` 无法打开数据库文件

**诊断与修复**：

```bash
# 1. 检查是否有其他进程在使用数据库
lsof bilibili_monitor.db
fuser bilibili_monitor.db

# 2. 如果有残留进程，终止它们
kill $(fuser -t bilibili_monitor.db)

# 3. 备份当前数据库
cp bilibili_monitor.db bilibili_monitor.db.backup.$(date +%F)

# 4. 尝试修复数据库
sqlite3 bilibili_monitor.db "PRAGMA integrity_check;"

# 5. 如果修复失败，从备份恢复
```

```python
# 建议：实现分层错误处理和自动重试
import time
from functools import wraps

def retry_with_backoff(max_retries=3, base_delay=1):
    """带指数退避的重试装饰器"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(max_retries):
                try:
                    return func(*args, **kwargs)
                except requests.exceptions.RequestException as e:
                    if attempt == max_retries - 1:
                        raise
                    delay = base_delay * (2 ** attempt)
                    logger.warning(f"第{attempt+1}次重试，等待{delay}秒...")
                    time.sleep(delay)
            return None
        return wrapper
    return decorator

@retry_with_backoff(max_retries=3, base_delay=2)
def fetch_bilibili_data(url):
    response = requests.get(url, timeout=30)
    response.raise_for_status()
    return response.json()
```

```python
class DataValidator:
    REQUIRED_FIELDS = ['title', 'author', 'views', 'published_at']

    @classmethod
    def validate(cls, record):
        errors = []

        # 1. 必填字段检查
        for field in cls.REQUIRED_FIELDS:
            if not record.get(field):
                errors.append(f"缺少必填字段: {field}")

        # 2. 数据范围校验
        if record.get('views', 0) < 0:
            errors.append(f"播放量为负数: {record['views']}")

        # 3. 日期合理性检查
        pub_date = record.get('published_at')
        if pub_date:
            try:
                parsed_date = datetime.fromisoformat(pub_date)
                if parsed_date > datetime.now():
                    errors.append(f"发布日期在未来: {pub_date}")
                if parsed_date.year < 2010:
                    errors.append(f"发布日期过早: {pub_date}")
            except ValueError:
                errors.append(f"日期格式无效: {pub_date}")

        # 4. 去重检查（基于唯一标识）
        unique_key = cls.generate_unique_key(record)
        if cls.is_duplicate(unique_key):
            errors.append(f"重复数据: {unique_key}")

        return len(errors) == 0, errors

    @staticmethod
    def generate_unique_key(record):
        # 使用 BV号 + 发布时间作为唯一标识
        return f"{record.get('bvid')}_{record.get('published_at')}"

    @classmethod
    def is_duplicate(cls, unique_key):
        with get_db_connection() as conn:
            cursor = conn.cursor()
            cursor.execute(
                "SELECT COUNT(*) FROM videos WHERE unique_key = ?",
                (unique_key,)
            )
            return cursor.fetchone()[0] > 0
```

```bash
python scripts/collect.py --brand "LimX"     # 单个品牌

# 查看状态
cat collect_status.json                      # JSON格式
sqlite3 bilibili_monitor.db "SELECT ..."     # SQL查询

# 服务管理（Systemd）
systemctl restart bilibili-monitor.service   # 重启
journalctl -u bilibili-monitor.service -f    # 实时日志

# 日志查看
tail -f logs/collect.log                     # 实时日志
grep "ERROR" logs/collect.log | wc -l        # 错误统计
```
